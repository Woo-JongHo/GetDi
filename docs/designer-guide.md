# GetDi 사용 설명서

> **한 줄로**: NN/g의 2026년 기사를 직접 긁어와서, 읽고, 요약하고,
> 인스타 카드 초안까지 만드는 도구다.

이 문서는 개발을 해 본 적 없는 사람을 기준으로 썼다.
터미널에 몇 줄을 붙여넣는 것이 전부이고, 각 단계마다
**무엇이 보이면 성공인지**를 함께 적었다.

마지막 10장은 "코드를 읽고 싶을 때" 어디부터 보면 되는지다.

### GetDi 폴더로 이동하는 법

터미널에 `cd `를 입력한다.
`cd` 뒤에 공백 하나를 둔다.
Finder에서 **GetDi 폴더를 터미널 창으로 끌어 놓고** 엔터를 누른다.
컴퓨터마다 설치 위치가 달라서 이 문서에 특정 사용자의 경로를 적지 않는다.

## Claude Code로 안내받기

Claude Code를 쓰고 있다면 이 문서를 처음부터 외울 필요가 없다.

```bash
claude
```

위 명령은 먼저 GetDi 폴더로 이동한 뒤 실행한다.

Claude Code가 열리면 아래처럼 입력한다.

```text
/designer-guide
```

현재 컴퓨터를 읽기 전용으로 점검한 뒤, 막힌 첫 단계의 명령 하나와
성공했을 때 보일 문구를 차례로 알려준다. 모델 연결만 궁금하면
`/designer-guide api`, 작업 순서는 `/designer-guide workflow`라고 입력한다.

### 모델은 어떻게 연결되나

```text
브라우저 화면
  → localhost:5545의 /api/*
  → Vite 로컬 서버
  → server/model.mjs
  → 내 컴퓨터의 claude 또는 codex CLI
  → 그 CLI에 로그인한 계정
```

GetDi 저장소에 API key를 붙여넣는 구조가 아니다. `claude`나 `codex`에
로그인이 필요하면 각 CLI가 보여 주는 로그인 화면에서만 진행한다.
채팅이나 `.env` 파일에 key·token·cookie를 적지 않는다.

읽기 전용 화면용 `public/snapshot/`도 로컬에서 만들며 Git에는 올리지 않는다.
번역·분석·초안 생성은 로컬에서만 된다.

---

## 1. 이 도구가 하는 일

Nielsen Norman Group(NN/g)은 UX 연구로 오래된 기관이다.
GetDi는 그곳의 2026년 기사를 가져와 이렇게 만든다.

1. 기사 목록과 본문을 받아온다 — 이미지까지 같이 받는다
2. 한국어로 번역한다
3. 무엇이 핵심인지 분석한다
4. 인스타 카드 6장 안팎의 문구 초안을 만든다
5. 말로 고쳐 달라고 하면 새 버전을 만든다

**아직 안 되는 것**: 완성된 이미지 파일로 뽑기, 인스타에 자동으로 올리기.
문구와 배치 계획까지가 지금 범위다.

## 2. 준비 — Node를 깐다 (처음 한 번만)

이 도구는 Node라는 프로그램 위에서 돈다. 먼저 그것이 있는지 본다.

터미널을 연다. (Mac은 `⌘ + 스페이스` → `터미널` 입력 → 엔터)

아래를 붙여넣고 엔터.

```bash
node --version
```

**성공 신호**: `v22.0.0`처럼 `v` 다음에 숫자가 나온다.
앞 숫자가 **20 이상**이면 된다.

`command not found`가 나오거나 숫자가 20보다 작으면 Node를 깔아야 한다.

1. https://nodejs.org 에 들어간다
2. **LTS**라고 적힌 초록 버튼을 누른다 (두 개 중 왼쪽)
3. 받아진 파일을 열고 계속 → 계속 → 설치를 누른다
4. **터미널 창을 완전히 닫았다가 새로 연다** (이걸 안 하면 방금 깐 걸 못 찾는다)
5. `node --version`을 다시 쳐서 숫자가 나오는지 본다

---

## 3. 처음 한 번만 하는 준비

터미널에 아래를 한 줄씩 붙여넣는다.

먼저 위의 **GetDi 폴더로 이동하는 법**을 따라 이동한다.

```bash
npm install
```

`npm install`은 이 도구가 쓰는 부품들을 받아오는 작업이다.
1~2분 걸리고, 중간에 글자가 빠르게 지나간다. 정상이다.

**성공 신호**: 마지막에 `added ... packages` 같은 줄이 뜨고 입력 커서가 돌아온다.
`npm ERR!`로 시작하는 빨간 글씨가 없으면 된 것이다.

이 단계는 **처음 한 번만** 하면 된다.

## 4. 켜기와 끄기

### 켤 때

먼저 GetDi 폴더로 이동한 뒤 실행한다.

```bash
npm run dev
```

**성공 신호**: 터미널에 이런 줄이 뜬다.

```
  ➜  Local:   http://localhost:5545/
```

브라우저 주소창에 `http://localhost:5545/`를 넣고 연다.
왼쪽 위에 검은 동그라미와 **GetDi**가 보이면 성공이다.

### 끌 때

터미널에서 `Control` + `C`를 누른다.

브라우저 탭만 닫으면 뒤에서 계속 돌고 있다.
**터미널 창은 켜 둔 채로 둔다.** 창을 닫으면 사이트도 함께 꺼진다.

## 5. 화면 넷 = 일하는 순서

맨 위 줄에 번호가 붙은 메뉴 네 개가 있다.
왼쪽에서 오른쪽이 곧 작업 순서다.

| | 메뉴 | 언제 쓰나 |
|---|---|---|
| 01 | 크롤링 | 기사를 받아올 때. 처음 한 번, 그리고 새 기사가 나왔을 때 |
| 02 | 카드 리스트 | 받아온 기사 중에 만들 것을 고를 때 |
| 03 | 요약본 | 고른 기사를 읽고 이해할 때 |
| 04 | 인스타 초안 | 카드 문구를 만들고 고칠 때 |

오른쪽 끝의 **사용법**은 이 문서다. 작업 단계가 아니라서 번호가 없다.

---

## 6. 01 크롤링 — 기사 받아오기

**수집 시작**을 누른다. 그러면 아래가 순서대로 일어난다.

1. 기사 목록을 훑는다 (몇 분)
2. 기사를 하나씩 열어 본문과 이미지를 받는다 (오래 걸린다)

### 왜 이렇게 오래 걸리나

NN/g가 **"요청 사이에 60초를 쉬어라"**라고 정해 두었다.
그것이 그 사이트의 규칙이고, 이 도구는 그 규칙을 지킨다.

2026년 7월 기준으로 기사가 59건이었고, 목록까지 합쳐 **한 시간 남짓** 걸렸다.
고장이 아니다. 화면에 `다음 요청까지 47초 기다리는 중`처럼 남은 시간이 나온다.

### 기다리는 동안

- **브라우저를 닫아도 된다.** 수집은 계속 돈다
- **중간에 중지해도 된다.** 다시 시작하면 받다 만 곳부터 이어받는다
- 터미널만 끄지 않으면 된다

**성공 신호**: 위쪽 막대가 오른쪽으로 차고, `본문 12 / 87건`처럼 숫자가 는다.
끝나면 초록색 **수집 완료**가 뜬다.

### 실패가 몇 건 뜬다면

정상 범위다. 아래 **실패한 것** 칸에 어떤 기사가 왜 실패했는지 나온다.
다시 **수집 시작**을 누르면 실패한 것만 다시 시도한다.

### 아래쪽 접힌 칸 둘

- **AI를 얼마나 썼는지 보기** — 토큰을 얼마나 썼는지
- **모델이 주고받은 내용 보기** — AI에 무엇을 보냈고 무엇을 받았는지

평소에는 안 봐도 된다. 궁금할 때만 편다.

## 7. 02 → 03 → 04, 카드 만들기

### 02 카드 리스트에서 고르기

받아온 기사가 카드로 깔린다. 왼쪽에서 **월별**로 좁히거나 검색할 수 있다.

카드마다 상태가 있다.

- **본문 준비됨** — 다음 단계로 갈 수 있다
- **수집 대기** — 본문을 아직 못 받았다. 눌러도 안 열린다

**본문 준비됨** 카드를 누르면 요약본으로 들어간다.

### 03 요약본에서 이해하기

왼쪽에 보기 방식 셋이 있다.

- **요약** — 이 글이 무슨 말인지. 여기가 기본이다
- **한국어 전문** — 전체 번역
- **원문** — 손대지 않은 영어 본문

처음 들어가면 요약이 비어 있고 **이 기사 분석하기** 버튼이 있다.
누르기 전에는 아무 일도 안 일어난다. **돈이 드는 작업이라 일부러 수동이다.**

번역도 마찬가지로 **한국어 번역 시작**을 눌러야 한다.
둘 다 처음 한 번만 시간이 걸리고, 그다음부터는 저장된 것이 바로 뜬다.

본문의 문단이나 이미지를 누르면 오른쪽에 그 부분이 근거로 잡힌다.
"이 말이 원문 어디서 나왔나"를 확인할 때 쓴다.

### 04 인스타 초안 만들기

요약본 오른쪽 아래의 **이 글로 카드 생성**을 누른다.

만들어지는 것은 **문구와 배치 계획**이다. 완성된 그림 파일이 아니다.

고치고 싶으면 말로 쓴다.

```
3번 카드 제목이 너무 딱딱해. 질문형으로 바꿔줘.
```

고칠 때마다 **새 버전이 쌓인다.** 이전 버전은 사라지지 않으니 마음껏 시켜도 된다.

아래 접힌 칸의 **참고한 인스타 게시물 분석 보기**를 펴면,
이 카드들이 어떤 레퍼런스를 근거로 만들어졌는지 볼 수 있다.

## 8. 이 도구가 까다롭게 구는 이유

가끔 "못 하겠다"고 하거나 빈칸으로 둔다. 고장이 아니라 일부러 그렇게 만들었다.

**원문에 없는 말은 만들지 않는다.**
그럴듯한 숫자나 사례를 지어내면 그 카드는 나중에 못 쓴다.
그래서 근거가 없으면 아예 안 쓴다.

**원문의 말투를 세게 바꾸지 않는다.**
원문이 "그럴 수도 있다"고 했으면 "그렇다"로 바꾸지 않는다.

**출처가 불분명한 이미지는 내보내지 않는다.**
화면에서는 보이지만 최종 결과물에는 안 담긴다.

**참고한 계정의 캐릭터나 로고는 따라 그리지 않는다.**
구조와 분위기만 참고 대상이다.

카드 문구가 밍밍하게 느껴진다면 대개 원문에 근거가 약해서다.
그럴 때는 다른 기사를 고르는 편이 빠르다.

## 9. 막혔을 때

**브라우저에 아무것도 안 뜬다**
터미널이 아직 켜져 있는지 본다. 꺼졌으면 `npm run dev`를 다시 친다.

**`command not found: npm`**
Node가 안 깔렸거나, 깔고 나서 터미널을 새로 안 열었다. 2장으로 돌아간다.

**`cd: no such file or directory`**
경로가 다르다. Finder에서 프로젝트 폴더를 터미널 창으로 끌어다 놓으면
경로가 자동으로 입력된다. `cd ` 를 먼저 치고 끌어다 놓는다.

**수집이 멈춘 것 같다**
`다음 요청까지 N초`가 보이면 정상이다. 60초씩 쉬는 중이다.
아무 표시도 없고 몇 분째 그대로면 **중지** 후 **수집 시작**을 다시 누른다.

**번역이나 분석이 안 끝난다**
크롤링 화면 아래 **모델이 주고받은 내용 보기**에서 지금 무슨 작업이 도는지 볼 수 있다.

**카드가 마음에 안 든다**
04 화면에서 계속 고쳐 달라고 하면 된다. 버전이 쌓일 뿐 원본이 망가지지 않는다.

## 10. 코드를 읽고 싶다면

읽는 순서를 데이터가 흐르는 순서와 맞췄다. 위에서부터 내려가면 된다.

### 먼저 볼 파일 넷

| 파일 | 무엇을 배우나 |
|---|---|
| `crawler/robots.mjs` | 남의 사이트를 긁을 때 지켜야 하는 규칙을 코드가 어떻게 지키는가 |
| `crawler/listing.mjs` | HTML 덩어리에서 필요한 것만 뽑아내는 법 |
| `crawler/detail.mjs` | 본문을 안전하게 정제하면서 순서를 보존하는 법 |
| `crawler/run.mjs` | 오래 걸리는 작업을 중단·재개 가능하게 만드는 법 |

각 파일 맨 위에 **이 파일이 왜 이렇게 생겼는지**를 적어 두었다.
"무엇을 하는가"보다 "왜 그렇게 했는가"가 더 오래 쓸모 있다.

### 화면 쪽

`src/main.jsx`가 출발점이다. 화면 넷이 어떻게 연결되는지 여기 다 있다.
그다음 `src/features/crawl/CrawlWorkspace.jsx`를 보면
"서버에서 상태를 읽어 화면에 그리는" 기본 패턴이 보인다.

### 코드가 맞는지 확인하는 법

```bash
npm test
```

크롤러·서버·스크립트·온보딩 진단 테스트가 전부 통과해야 한다.
검사 항목은 각 `*.test.mjs` 이름이 그대로 설명한다.
별도 결과 보고서를 복사해 두지 않고 실행 결과를 현재 근거로 사용한다.

### 고쳐 보고 싶다면

`npm run dev`를 켜 둔 채로 파일을 고치고 저장하면
브라우저가 **알아서 새로고침된다.** 껐다 켤 필요 없다.

망가뜨려도 된다. `git status`로 무엇을 바꿨는지 보고,
되돌리고 싶으면 `git checkout -- 파일이름`을 친다.
